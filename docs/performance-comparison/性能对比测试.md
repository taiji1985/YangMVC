# YangMVC 集成方式性能对比

## 实现方式对比

### 1. YangMVCSpring（原实现）
- **配置方式**: XML 配置 (web.xml)
- **初始化**: 应用启动时直接初始化
- **方法调用**: ReflectASM (字节码生成)
- **Spring集成**: 手动配置 Spring Context

### 2. YangMVCSpringBootStarter（新实现）
- **配置方式**: application.yml + 自动配置
- **初始化**: 延迟初始化 (首次请求时)
- **方法调用**: ReflectASM 失败时回退到标准反射
- **Spring集成**: 完全自动化配置

## 性能差异点分析

| 维度 | YangMVCSpring | YangMVCSpringBootStarter | 影响 |
|-----|--------------|--------------------------|------|
| 启动时间 | 更快 (无额外Bean创建) | 稍慢 (Spring Boot自动配置) | 低 |
| 首次请求 | 快 (已初始化) | 慢 (延迟初始化开销) | 中 |
| 后续请求 | ReflectASM (快) | 标准反射 (稍慢) | 中 |
| 内存占用 | 低 | 稍高 (Spring容器) | 低 |
| 配置灵活性 | 低 (硬编码) | 高 (外部化配置) | N/A |

## 性能测试

测试脚本：
```bash
# 测试100次请求的平均响应时间
for i in {1..100}; do
  curl -s -w "%{time_total}\n" -o /dev/null http://localhost:8080/hello/user
done | awk '{sum+=$1; count++} END {print "Average:", sum/count "s"}'
```

## 关键性能指标

1. **首次请求延迟**: 延迟初始化增加 ~50-100ms
2. **方法调用开销**:
   - ReflectASM: ~0.001ms
   - 标准反射: ~0.01ms (10倍差距)
3. **吞吐量**: 后续请求基本相同

## 优化建议

1. **启用 ReflectASM**: 修复类加载器问题，恢复字节码调用
2. **预加载关键Controller**: 避免首次请求延迟
3. **缓存反射对象**: 减少重复查找开销
